MyTempleKnowledge 界面 UI 审计：主题体系与三种文档视图的渲染一致性

针对「企业级审美 · 专精 · 轻松自然 · 和谐美观 · 交互流畅」这一目标，对 public/styles.css（11,578 行）与三种文档视图（编辑 / 预览 / 沉浸）做了静态解析 + 无头浏览器实测。结论是：颜色层已经达到不错的自然调性，真正的短板在「度量层」与「令牌层」——同一个段落在三种视图里用的是不同的字体、不同的行高、不同的版心推导方式，而支撑这套外观的令牌体系有 1/5 是空的或重复的。

01执行摘要

一句话诊断：颜色是「风格」，度量是「秩序」。这个项目的颜色已经有风格了，但度量还没有秩序。三种视图各自维护自己的字体栈、行高与版心公式，加上令牌层缺失，导致同一份文档在切换视图时会「换一副面孔」——这在企业级产品里是最容易被感知为「不够精致」的一类问题，而它恰恰不靠审美品味解决，靠规范解决。

02审计方法（可复现）

全部结论都有数据来源，不依赖主观判断或截图观感：

  1. 令牌与尺度静态解析：写了一个 CSS 解析器，逐字符跟踪括号深度，提取每个自定义属性的「定义选择器 + 值 + 行号」，再与实际引用位置做差集。产出 107 个变量的定义/引用矩阵。（.verify/audit-css.mjs）
  2. 计算样式实测：用 puppeteer-core + 本机 Edge 无头模式加载真实 public/styles.css，构造三视图真实的祖先链（app-shell.immersive > .editor-panel > #editor > .cm-editor > .cm-scroller > .cm-content > .cm-line），通过 CDP CSS.getComputedStyleForNode 取权威计算值，覆盖 4 个主题 × 3 种视图。（.verify/probe-run.mjs）
  3. 对比度计算：按 WCAG 2.x 相对亮度公式计算，rgba() 值先按 alpha 合成到主题底色上再比对，避免「半透明面板算不准」的常见误判。

一个方法论提醒（本次踩到的坑）：在同一帧内 element.classList.add() 之后立刻 getComputedStyle() 读取，在无头 Chromium 里可能返回陈旧的层叠结果——我第一轮实测因此得到「沉浸模式的居中版心完全没生效」的错误结论。改用 CDP 权威接口 + 帧间等待后，真实读数是生效的。凡是「CSS 计算样式」结论，都必须用可以复现的取值路径验证。

03诊断一：令牌层有 1/5 是空的或重复的

样式表里定义了 107 个自定义属性，看起来体系很完整。但解析后发现两个结构性问题：（a）23 个变量被引用却从未定义，（b）主题覆盖不成矩阵。

3.1 幽灵变量：引用了，但从来没有定义

这 23 个变量在所有主题里都不存在。有回退值的还能工作；没有回退值的 9 处声明会被整条丢弃——这类问题不会报错，只会「静默失效」，是最难排查的一类样式缺陷。

这是 v2.1.32「沉浸排版对齐预览栏」的承诺在 字号 ≤ 15.4px 区间内失效。
渲染块的外边距叠加在行盒之上 P1 沉浸渲染容器只把「首末子元素」的 margin 归零，块与块之间仍走 .markdown-body 的元素级外边距（p{margin-bottom:1em}、h2{margin:1.7em 0 .7em}），而源码行只有 padding-block: 1px。结果：块间距与行间距属于两套不同的排版逻辑，无法用同一个节律表达。
段落未渲染 → 语法标记裸露 P1 块级识别刻意收窄（「普通段落不动」是控风险的正确决策），行内只接管了 {color|bg|size:…} 与 $…$。因此 **加粗**、[链接](url)、`代码`、~~删除~~ 在沉浸模式下仍以源码形式显示——标题/表格/代码块是所见即所得，段落不是。
叠加「等宽字体」，观感就是「半渲染的 Markdown 编辑器」，而非「写作即成品」。

值得肯定的部分（改进时不要动）

  • 版心换算比例是对的。实测：阅读/预览 920px @ 16px = 57.5em；沉浸 956.8px @ 16.64px = 57.5em。字号 ×1.04 与版心 ×1.04 同源等比，保证了两侧换行位置一致——这是很专业的一个决定，应保留并升格为令牌公式。
  • 渲染容器复用 .markdown-body 类（436 条排版规则），而不是手写副本——历史手写副本被轻量模式反制而从未生效的教训已经被正确吸收，这个架构选择应该继续沿用。
  • 沉浸模式的空行收缩（--mt-immersive-blank-line: 16px，且注释明确警告「不得归零否则光标消失」）、报错区限高（180px + 内滚）、隐藏行号栏，都是从真实问题里长出来的细节，方向正确。

5.1 根因：一个令牌，三种角色

--accent 同时在承担三件事，而这三件事对「明度」的要求是互相冲突的：

  • 角色 A · 实心控件底（button.primary、.view-mode-switch button.active、#graphBtn.active）→ 要求它足够深，才能承载白字 ≥4.5:1；
  • 角色 B · 正文强调色（--md-link、--accent-strong）→ 要求它足够深且饱和，才能与浅底拉开 ≥4.5:1；
  • 角色 C · 大面积图形/柔光底（--hover-bg、--accent-wash、背景径向渐变）→ 要求它足够浅，才能只做氛围不抢焦点。

结果就是数学上没有解：护眼主题的 #88a956 是漂亮的「自然绿」，做氛围极好（角色 C），但白字压上去只有 2.67:1（角色 A 失败）。暗色主题的 #7ab89a 同理——它是浅薄荷绿，正确做法是配深色文字，而现在配的是白字（2.29:1）；更糟的是 .recent-item.active 用的是 --text（#c5bfb2 浅米色）压在同为浅色的 #7ab89a 上——1.25:1，实际几乎不可读。

结论：不是「调一下色值」的问题，是「令牌少了两个」的问题。需要把 --accent 拆成 --accent-solid（实心底）、--on-accent（其上的文字色）、--accent-text（正文/链接强调色）三个，各自独立取值并各自校验。

06诊断四：交互、密度与工程治理

6.1 状态不可分辨

全局按钮的 hover 与「选中」在视觉上几乎等价：

button:hover, button.active { border-color: var(--accent); color: var(--accent-strong); }

两者只改边框色与文字色，都不改背景。这意味着：鼠标悬停在一个按钮上时，你无法判断它是「因为我hover了」还是「它本来就是当前激活项」。模式切换（阅读/修改）尤其依赖这个状态，用户会持续困惑「我现在到底在哪个模式」。

叠加第二个问题：#modeToggleBtn 的文案表示的是「将要切换到的模式」——处于阅读模式时按钮写着「修改」，处于编辑模式时写着「阅读」；而它的 .active 类又表示「当前是否处于编辑」。同一个控件上，文案用一套语义、高亮用另一套语义。

08改进方案

整体思路：不是重新设计外观，而是把已经存在的外观「收进规范」。四条主线——令牌分层、度量统一、状态与密度规范、工程护栏。全部改动都只作用于 CSS 变量值与选择器组织，不触碰任何功能逻辑与既有类名契约。

8.1 主线一：一套度量（收益最大，风险最低）

把「正文怎么写」抽成唯一一组令牌，三处视图只引用它：

:root{ --prose-size: var(--doc-font-size); /* 唯一出处 */ --prose-leading: 1.78; /* 唯一行高，四主题共用 */ --prose-measure: 920px; /* 唯一版心 */ --prose-scale: 1.04; /* 沉浸放大系数，字号与版心同源 */ } /* ① 阅读模式 */ .reader-panel > .markdown-body{ font-size:var(--prose-size); line-height:var(--prose-leading); width:min(var(--prose-measure),calc(100% - 42px)); } /* ② 分栏预览 */ #preview.markdown-body{ font-size:var(--prose-size); line-height:var(--prose-leading); } /* ③ 沉浸模式（字号与版心用同一系数） */ .app-shell.immersive #editor .cm-content{ font-size: calc(var(--prose-size) * var(--prose-scale)); /* 去掉 max(16px,…) 下限 */ line-height: var(--prose-leading); /* 与源码行同值 → 不再跳变 */ padding: 36px max(24px, calc((100% - var(--prose-measure) * var(--prose-scale)) / 2)) 55vh; } /* ④ 沉浸渲染容器：只中和容器属性，字体/行高交给上面统一 */ .app-shell.immersive .cm-line .mt-md-wysiwyg.markdown-body{ font-family: var(--prose-font); /* = --app-font-family，跟随用户设置 */ font-size: inherit; line-height: inherit; /* 继承版心，不再各写 1.82 */ }

为什么这一步收益最大：字号与版心同乘 --prose-scale，em 宽度恒定 → 三种视图换行位置一致；行高取同一个值 → 光标移动不再引起行高跳动；去掉 max(16px,…) 下限 → 小字号用户的设置被真正尊重。而且这一改不需要动任何 DOM 结构或 JS。

8.3 主线三：沉浸模式补全 WYSIWYG（消除「半渲染」感）

复用已经过验证的 InlineStyleWidget 机制（只替换标记字符范围 + 范围原子化 + 未闭合保持源码），把行内语义纳入同一套：

语法现状建议复用机制
**粗体** / *斜体*源码裸露（等宽显示星号）渲染为 <strong>/<em>新增 InlineMarkWidget，与 InlineStyleWidget 同一模式
[文字](url)源码裸露渲染为链接，保留 title 与 Ctrl+点击打开同上
`代码`源码裸露渲染为行内代码样式同上（注意与现有的 $…$ 范围互斥）
~~删除~~ / ==高亮==源码裸露渲染为 <del>/<mark>同上（<mark> 黄底需注意轻量模式的 revert 放行，已有先例）
{color|bg|size:…}已渲染保持InlineStyleWidget
$…$ / $$…$$已渲染保持InlineMathWidget

一个必须配套的决定：沉浸正文改用无衬线（跟随用户设置），等宽只保留在代码块内。否则即使行内都渲染了，光标块仍是等宽 → 移动光标时那一行依然会「变脸」。如果希望保留「改的时候能看到源码」，建议做成按住 Alt 临时显形的按需模式，而不是把标记常驻。

  • 时长收敛为 3 档：--dur-1:120ms（悬停/聚焦）、--dur-2:200ms（面板/下拉）、--dur-3:320ms（页面级过渡）
  • 缓动统一 cubic-bezier(.2,.7,.3,1)，替换现有 15 种时长混用
  • prefers-reduced-motion 同时覆盖 transition 与 animation
  • 分隔条：网格列 3px → 10px，视觉线仍为 1px 居中绘制（::before{inset-inline:4px}）

  • 编辑器工具栏：常驻 ≤10 个（标题、加粗斜体下划线高亮、列表、引用/提示、代码、链接、表格、图片、公式），其余按现有 7 个下拉面板归组，溢出改为「⋯ 更多」按钮而非隐藏滚动条。
  • 状态栏：8 项 → 4 项（文档名 · 字数 · 光标 · 保存状态），字号 11px → 12px；创建时间/系统时间移入 hover 提示或文档信息浮层。
  • 模式切换：改为两段式 segmented control（「修改 | 阅读」），当前段高亮——文案表达位置、高亮表达状态，两套语义合一。

8.5 主线五：工程护栏（让审美可迭代）

  • 拆分样式表为 5 个源文件（tokens.css / base.css / components.css / modes.css / themes.css），构建时合并输出为现有 public/styles.css —— 对外路径与引用方式零变化，因此不影响 WebView2 缓存策略与打包。
  • 加校验测试（复用仓库现有 tests/*.test.js 的源码断言风格）：
    • 断言「所有 var(--x) 都有定义」——本次的 23 个幽灵变量会立即让测试变红；
    • 断言「颜色令牌在 4 个主题内定义齐全」；
    • 断言「.cm-content 的行高只来自 --prose-leading」——防止再出现 1.8/1.82 双字面量回归；
    • z-index 白名单 + 禁止新增 !important（存量逐步清零）。
  • 视觉回归快照：用本次已经跑通的 puppeteer-core + 本机 Edge 方案，对「3 视图 × 4 主题 = 12 个组合」输出计算样式基线 JSON。任何改动后比对差异即可，无需人工肉眼确认——这正好满足「要实测数据、不接受『应该没问题』」的验证要求。

10约束与风险

  • 不触碰功能：以上全部为 CSS 令牌值与选择器组织的调整，不改类名契约、不改 DOM 结构、不改任何 JS 逻辑与路由。沉浸模式的渲染机制（Compartment 热切换、光标块跳过、视口裁剪）保持不变。
  • PR-2 的可见变化需要提前知会：统一行高后，护眼/柔光主题的编辑器行高会从 1.82 回到 1.78，正文密度有极轻微变化；沉浸模式在小于 15.4px 字号下会变大。这是修复，但会被用户感知，建议进 changelog。
  • PR-3 需要真机验证：沙箱内 WebView2 无法启动（导航报 0x8007139F），行内装饰的命中/原子范围行为必须实机确认，尤其是「样式标记与公式范围重叠时公式让路」的既有约定需要继续遵守。

  • 本次未做任何生产代码改动。报告与分析脚本位于被 gitignore 之外需注意的临时目录 .verify/（提交前应删除），如需保留可移入 docs/。
