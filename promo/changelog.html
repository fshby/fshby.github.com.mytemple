v2.1.2 · 截图保存后再次截图失败修复 + 文字大小可调

  • 缺陷修复（screenshot.html confirmEdit）：截图保存后再次截图失败。
  • 根因：confirmEdit 中 bgImg/tagCounter/currentTool/currentWidth 等关键变量未重置；FileReader.onload 为异步回调，若 readAsDataURL 卡住或失败，窗口和截图锁永不释放，导致下次截图被锁阻塞。
  • 修复：
    • confirmEdit 完整重置所有全局变量（bgImg/scaleX/scaleY/bgImgWidth/bgImgHeight/tagCounter/currentTool/currentColor/currentWidth/currentFontSize）。
    • toBlob 添加 5s 超时保护：Promise.race 竞争 toBlob 和 setTimeout，防止 Canvas 污染导致 toBlob 永不回调。
    • FileReader 添加 5s 超时保护 + onerror 回调：超时或出错时走 closeWindow 兜底释放锁和窗口。
    • drawImage 添加 try-catch：防止 bgImg/annoCanvas 异常时抛错导致后续清理代码不执行。
    • 健壮性检查：confirmEdit 入口检查 region/bgImg/annoCanvas/scaleX/scaleY 是否有效，无效时直接 cleanupAndClose。
    • cleanupAndClose 也完整重置所有变量（含 bgImg/scaleX/scaleY/tagCounter/currentFontSize 等）。
  • 新功能（文字大小可调）：
    • 新增 FONT_SIZES = [14, 18, 24, 32] 四档字体大小。
    • 工具栏新增字体大小按钮区域，点击切换字体大小，选中高亮。
    • showTextInput 使用 currentFontSize 替代硬编码 16px。
    • 文字标注创建使用 currentFontSize 替代硬编码 18。
    • 编辑文字时切换字体大小可实时同步到输入框。
  • 不影响其他功能：仅修改 screenshot.html。录屏功能、AI 功能、知识库管理不受影响。无遮罩干扰。

v2.1.1 · 截图选区边界约束（选区框越界难以选中）

  • 缺陷修复（screenshot.html）：自定义截图区域过大靠近屏幕边界时选区框出现在边界外难以选中。
  • 根因：startRegionSelection 的 onDown 直接 startX = curX = e.clientX、onMove 直接 curX = e.clientX，鼠标坐标未经任何边界约束。当用户拖拽到屏幕边缘/外时，选区框坐标超出视口范围（负值或超过 innerWidth/innerHeight），选区框部分或全部跑到屏幕外，用户难以选中框边缘进行操作。
  • 修复：
    • onDown：startX/curX 用 Math.max(0, Math.min(e.clientX, window.innerWidth)) 约束；startY/curY 同理。
    • onMove：curX/curY 用同样的 clamp 约束，确保拖拽过程中选区框始终在视口内。
    • onUp：最终 region 对象也 clamp（x 不超过 innerWidth-w，y 不超过 innerHeight-h）作为防御性保底。
    • 工具提示（tooltip）位置也 clamp 到视口内（left 不超过 innerWidth-120，top 不超过 innerHeight-30）。
  • 健壮性增强：三层边界约束（onDown + onMove + onUp），任一层失效也有下一层保底。工具提示不会跑到屏幕外不可见。
  • 不影响其他功能：仅修改 screenshot.html 的 startRegionSelection 函数内 onDown/onMove/onUp 和 draw 的 tooltip 位置逻辑。录屏功能、AI 功能、知识库管理不受影响。无遮罩干扰（截图窗口已有 always_on_top + 透明 + 全屏覆盖，选区框在 canvas 内绘制不会遮挡鼠标）。

v2.1.0 · 录屏功能稳定性加固（多次录制失败 + 桌面选择器 + 状态清理）

  • 第二次及后续录制失败修复（global_capture.rs + recorder.html）：根因为 show_recorder_window 复用已有录屏窗口时仅 set_always_on_top + unminimize + show，不 reload 页面。前端 recording/recorder/chunks/region 等变量残留上次录屏状态，DOM 已被 document.body.innerHTML='' 清空，init() 不再执行 → 用户看到空白窗口无法操作；或 api_start_native_record 因前端状态错乱失败 → 降级到 getDisplayMedia 弹出桌面/窗口选择器。修复：复用窗口时 eval window.location.href='recorder.html?_t=时间戳' 重新加载页面，确保 init() 重新执行、所有 JS 变量重置。
  • 录屏默认录桌面不弹选择器修复：根因同上。RecordState 残留为 Some 导致 start_native_record 返回「录屏已在进行中」→ 前端降级到 getDisplayMedia 弹出选择器。修复后窗口 reload 确保前端状态干净，api_start_native_record 成功走 xcap DXGI 桌面捕获（无选择器）。close_recorder_window 已有的 stop_native_record 兜底 + 新增页面 reload 双重保险确保 RecordState 不残留。
  • stop_native_record 健壮性增强（global_capture.rs）：原代码 state.recorder.stop() 可能阻塞或 panic，如果 panic 会卡住 Mutex 锁导致后续所有录屏操作死锁。修复：用 std::panic::catch_unwind(AssertUnwindSafe) 包裹 recorder.stop()，即使 panic 也确保 guard.take() 已移除 RecordState，锁正常释放。
  • handle_recorder_result 保存后清理 + 健壮性：保存成功后执行 stop_native_record + release_record_lock + 清理 pending_record_bg 临时文件 + emit recorder-saved 事件（含 path/filename/size）。保存失败也释放锁和状态防止卡住。新增空内容校验：bytes.is_empty() 时跳过保存返回错误。
  • close_recorder_window 页面重置：关闭窗口后 eval 导航到 about:blank，下次 show_recorder_window 复用时 reload 到 recorder.html 获得干净状态。
  • 前端状态完整重置（recorder.html）：cleanupAndClose 完整重置 recording/timerInterval/recorder(MediaRecorder.stop)/chunks/overlay/canvas/ctx/outCanvas/outCtx/frameImg/bgImg/region/elapsed 全部变量。stopRecording 保存 recorder/chunks 到临时变量 savedRecorder/savedChunks，保存完成后 recorder=null/chunks=[] 清理引用；FileReader.onerror 也走 cleanupAndClose 防止卡住。等待最后一帧从 200ms 增加到 300ms 确保数据完整性。
  • 不影响其他功能：仅修改 show_recorder_window/close_recorder_window/stop_native_record/handle_recorder_result 后端函数和 recorder.html 前端 cleanupAndClose/stopRecording 函数。截图功能、AI 功能、知识库管理不受影响。无遮罩干扰（已有 always_on_top(false) + minimize + hide + 移出屏幕 多重保险）。

v2.0.9 · 知识库智能管理故障排查与稳定性增强

  • ai_reindex 内存浪费修复（handlers.rs）：原代码在更新 state.chunks 时执行 *chunks_ref = all_chunks.clone()，万级 chunk 场景下 clone 全量拷贝几十 MB 堆数据后再丢弃原 vec，造成无谓内存峰值。修复：改为 std::mem::take(&mut all_chunks) 零拷贝转移所有权。
  • ai_reindex 静默吞错修复（handlers.rs）：原代码 read_file_force 失败时 Err(_) => continue，既不记日志也不计数，用户无法知道哪些文件被跳过。修复：改为 Err(e) => log::warn 记录失败文件路径和错误 + skipped += 1；同时新增内容为空检查，空文件也跳过并计数。响应新增 skipped 和 totalFiles 字段，前端 Toast 显示「X/Y 文件跳过」。
  • ai_reindex 进度反馈修复（handlers.rs）：原代码 progress 字段在全量重建过程中从未更新（status() 返回的 progress 始终为 0,0），前端无法获知进度。修复：重建开始时设 (0, total_files)，逐文件递增 done，每 10 文件 log::info 输出进度，完成后设 (total, total)。
  • DeepSeek/Ollama 错误响应切片 panic 修复（rag.rs）：原代码 &text[..text.len().min(500)] 在错误响应包含多字节 UTF-8 字符时，500 字节位置可能落在字符中间导致 panic（与之前中文切片 bug 同类）。修复：chat_with_deepseek 和 chat_with_ollama 均改为 text.chars().take(500).collect::<String>()，按字符边界安全截断。
  • lexical_search 性能优化（rag.rs）：原代码在 O(chunks × unique_tokens) 双重循环中，每个 token 对每个 chunk 反复调用 chunk.title.to_lowercase() / heading / text，导致同一 chunk 被重复 lowercase 多次。修复：预计算 title_lower / heading_lower / text_lower 一次，循环内直接 contains 查找，降低 String 分配次数从 O(chunks × tokens) 到 O(chunks)。
  • 并发安全（handlers.rs）：ai_reindex 入口新增 progress 检查：若 total > 0 && done < total，直接返回 { ok: false, error: '索引重建正在进行中' }，防止用户快速点击或前端重试导致并发重建。
  • 前端改进（app.js）：aiReindexBtn 点击处理器增强：检测 result.ok === false 显示并发拒绝提示；正常路径 Toast 显示分块数、文档数、跳过数。
  • 不影响其他功能：仅修改 ai_reindex / lexical_search / chat_with_deepseek / chat_with_ollama 和前端 aiReindexBtn 处理器，不改变 API 路由结构、请求格式、响应基本结构（仅新增可选字段）。其他功能（截图/录屏/授权/AI 文本加工）不受影响。

v2.0.8 · AI 忠实性强约束 + 反幻觉机制

  • 选中文本加工忠实性约束（新增 AI_FAITHFULNESS_RULE）：适用模式 polish/rewrite/summary/keypoints/terms/comment。五重约束：① 严格基于原文：禁止编造/臆测/补充原文中不存在的事实、数据、引用、人名、日期、结论；禁止引入训练数据中的「常识」填补原文未提及的内容；信息不足时标注「【注意】原文中缺少XXX信息，已跳过」。② 不得篡改核心语义：可调整措辞与语序，但不得改变事实判断/观点立场/因果关系/数量关系（原文「可能」不得改「必然」，「A导致B」不得改「B导致A」）。③ 不得删减关键信息：可精简冗余表述，但不得删除关键事实/数据/条件/前提/限定词。④ 反幻觉自检：输出前逐句自问「这句话的信息是否直接来自原文？」若否则删除或替换为忠实转述。⑤ 用户自定义要求即硬边界。
  • 翻译模式忠实性强化：新增 4 条忠实性约束（译文不得擅自增加原文没有的信息；不得删减原文关键信息——每段每句每个术语必须有对应译文；不得篡改原文条件/因果/程度/时态等限定关系；逐句对照自检——原文几句译文几句）。自检提示从「有没有非目标语言字」扩展为「① 有没有非目标语言字 ② 有没有增删原文信息」。
  • 用户自定义要求硬边界化：所有模式的用户 instruction 从「用户额外要求：...」升级为「【用户自定义要求 — 硬边界，必须严格执行，不得偏离】」。inline-chat 新增「用户指令即硬边界」system prompt：用户设定的风格/字数/格式/视角/禁用词必须严格执行，不得以「更好」为由偏离；用户请求与文档上下文矛盾时以用户请求为准。
  • RAG 知识库反幻觉强化：新增 4 条反幻觉强约束：只能基于检索到的文档片段回答，不得引入训练数据外部信息；无相关信息时必须如实说明「检索到的文档中未包含相关内容」，不得编造；不得将碎片信息拼接臆测为完整结论；回答引用来源编号 [n] 可溯源验证。
  • 不影响其他功能：仅修改 AI system/user prompt 构造逻辑，不改变 API 路由/请求格式/响应结构/前端 UI。

v2.0.7 · 启动授权弹窗修复（WMI 缓存预热 + 超时放宽）

  • 启动未授权弹窗几秒后自动消失（缺陷修复）：软件每次启动后弹出「未授权」窗口，等待几秒后自动消失。根因：首次调用 /api/license/check 时，后端 verify_license 需通过 PowerShell 查询 WMI 获取硬件标识（Win32_Processor.ProcessorId、Win32_DiskDrive.SerialNumber、Win32_BaseBoard.SerialNumber、Win32_ComputerSystemProduct.UUID）和操作系统安装时间（Win32_OperatingSystem.InstallDate），单次查询耗时 2~5 秒。这些值虽有进程内缓存，但进程启动时缓存为空。前端 LICENSE_NET_TIMEOUT_MS=1500ms 超时导致 Promise.race 先返回 timeout，误判为未授权并弹出窗口；随后后台请求完成、缓存就绪，下一次 1.5s 轮询命中缓存才清除弹窗。
  • 后端预热缓存：license.rs 新增 pub fn prewarm_caches()，调用 get_machine_code()（触发 WMI 查询，写入 HARDWARE_CACHE + MACHINE_CODE_CACHE）和 get_system_reference_time()（触发 OS 安装时间查询，写入 SYSTEM_REF_TIME_CACHE）。lib.rs::run() 在 env_logger::init() 之后立即 std::thread::spawn 专用 OS 线程调用 prewarm_caches()，不阻塞启动流程。前端发起授权检查时缓存已就绪，verify_license 走缓存路径微秒级返回。
  • 前端超时放宽：LICENSE_NET_TIMEOUT_MS 从 1500ms 调整为 3000ms，为慢机器/首次冷启动留足余量（正常响应 <100ms，3s 仅为极端兜底）。
  • 不影响其他功能：prewarm_caches 仅在后台线程执行，不阻塞启动流程；超时放宽只影响授权检查，不改变其他 API 行为。

v2.0.6 · 截图/录屏健壮性加固（黑窗 + 遮罩挡鼠标 + 录屏选择器）

  • 截图勾选✓弹黑色命令窗口（缺陷修复）：截图区域勾选✓确认后屏幕闪现黑色 PowerShell/CMD 控制台窗口。根因：copy_image_to_clipboard 与 OCR 识别使用 std::process::Command::new("powershell") 启动子进程，未设置 CREATE_NO_WINDOW 标志，Windows 默认为控制台程序分配可见窗口。修复：两处 PowerShell 调用统一补 .creation_flags(0x08000000)（CREATE_NO_WINDOW），子进程不再弹黑窗。
  • 录屏后遮罩残留挡住鼠标（缺陷修复）：录屏结束/取消后录屏遮罩窗口仍覆盖屏幕，鼠标无法点击桌面与其他软件。根因：recorder.html 的 closeRecorderWindow() 调用 /api/screenshot/close，该端点执行 close_screenshot_window 只关闭截图窗口；录屏窗口（label=recorder）保持 always_on_top 可见，导致鼠标被遮挡。修复：新增独立 HTTP 端点 POST /api/recorder/close，执行 close_recorder_window 真正关闭录屏窗口（取消置顶→最小化→隐藏→移出屏幕）；recorder.html 改用 /api/recorder/close + IPC recorder_window_close 双重关闭。
  • 录屏默认不录系统桌面弹选择器（缺陷修复）：录屏时不默认录制系统桌面，而是弹出 getDisplayMedia 桌面/窗口选择器让用户选择。根因：取消/异常退出录屏时 cleanupAndClose() 未调用 api_stop_native_record，RecordState 残留为 Some；下一次 start_native_record 返回"录屏已在进行中"错误，前端降级到 navigator.mediaDevices.getDisplayMedia 弹出选择器。修复：close_recorder_window 兜底调用 stop_native_record 释放 RecordState；cleanupAndClose 显式调用 api_stop_native_record；确保任何关闭路径都释放原生录屏状态，下次直接走 xcap DXGI 桌面捕获（无选择器）。
  • 健壮性增强：新增 POST /api/recorder/result HTTP 降级端点（先关窗口再 spawn_blocking 后台保存），IPC 失败时录屏文件不丢失；recorder.html 停止录屏结果保存走 IPC recorder_result，失败降级 HTTP /api/recorder/result；close_recorder_window 统一兜底停止原生录屏 + 释放锁 + 多重保险隐藏窗口。

v2.0.5 · 截图核心缺陷彻底修复（多次截图失败 + 保存后卡死）

  • 多次截图失败根因修复：resetScreenshotUI() 中 const overlay = document.getElementById('screenshotOverlay') 声明了局部常量，遮蔽了全局 let overlay。随后 overlay = null 尝试给 const 赋值，在 ES Module 严格模式下抛出 TypeError，导致 loadAndShow 中断、isActive 卡在 true、轮询永久停止。修复：局部变量重命名为 oldOverlay/oldOcrModal，不再遮蔽全局。
