CORE CAPABILITIES

核心能力

不改变 Markdown 文件本身，围绕目录、图谱、检索、主题、性能与日常维护体验补强。

  1. 阅读与修改分开处理 — 阅读时强调目录与预览，编辑时强调输入稳定性与快捷键。
  2. 本地文件优先 — Markdown、图片、索引和工作区配置围绕本地目录组织，可迁移、可备份、可离线。
  3. 知识图谱 — 文档、标签和语义概念分层展示，图谱负责看关系，不替代文档结构。
  4. 长时间使用不刺眼 — 主题、字号、字体、背景和面板密度可调；柔光护眼主题默认降低对比度。
  5. 检索与维护省心 — 关键词检索、可选语义检索、Frontmatter 标准化、标签补全与主清单索引。
  6. 性能优化围绕真实场景 — 目录懒加载、增量解析、Worker 渲染、图谱自适应帧率。

BUILT-IN DOCS

使用文档

安装与启动

  1. 下载 Windows 安装包（.exe），双击运行。
  2. 选择安装目录，完成安装后桌面会出现快捷方式。
  3. 首次启动需选择工作目录（本地 Markdown 文件夹），之后自动记忆。
  4. 支持多工作路径，在设置中可添加、切换或移除。

文档编写规范

  • 支持标准 Markdown 语法，包括标题、列表、表格、代码块、引用等。
  • Frontmatter 支持(title、date、tags 等元信息字段)。
  • 文档间链接使用 [文本](相对路径.md) 格式，图谱会自动识别关联。
  • 支持数学公式（LaTeX 语法）、Mermaid 图表、Excalidraw 绘图。
  • 高亮标注块：:::tip / :::warning / :::note 等。

图谱标记与维护

  • 文档之间的链接关系自动生成知识神经图谱。
  • 最新文档自动居中，有链接的文档互相引力更强。
  • 拖拽节点松开后按引力规则缓慢复原。
  • 图谱运动参数可在设置中调节，不查看时不占用 GPU。

主题与外观

  • 内置深色、明亮、护眼、柔光四种核心主题。
  • 柔光主题：暖琥珀金强调色，低饱和度，适合长时间写作。
  • 图片主题：上传背景图并自动取色，支持文字明暗切换。
  • 字体、字号、窗口缩放均可自定义，重启后自动恢复。

可选辅助功能

  • 默认关闭，在设置中按需开启，不干扰核心编辑与阅读体验。
  • 支持本地或云端模型接入，模型配置在设置中填写。
  • 提供选中翻译、润色续写、代码补全与生成注释等辅助能力。
  • 问答侧栏助手回复可一键润色、续写或插入到当前文档。
  • 所有辅助功能均可独立开关，按需使用。

快捷键参考

  • Ctrl+B 加粗 · Ctrl+I 斜体 · Ctrl+K 链接
  • Ctrl+1/2/3 一/二/三级标题 · Ctrl+S 保存
  • Ctrl+F 关键字检索 · Ctrl+Shift+F 沉浸编辑 · Esc 退出沉浸
  • Tab 缩进 · Ctrl+Shift+7/8 有序/无序列表

可选辅助快捷键

  • Ctrl+Shift+A 代码补全 · Ctrl+Shift+/ 生成注释
  • Ctrl+Shift+P 润色 · Ctrl+Shift+X 续写
  • Ctrl+U 顶部智能检索 · Ctrl+I 行内对话
  • 辅助快捷键需在设置中开启对应功能后生效

v1.8.105 更新日志 · 全局搜索中文 MD「打不开/没内容」空白屏·三重修复

  • 【用户现象】v1.8.104 反馈：在顶部全局搜索（Ctrl+U）输入「江西电信」搜到 江西电信MR622-MK.md → 点击条目 → 左编辑栏/右阅读栏全白，底部 Toast 偶尔不报错误，但内容打不开。
  • 【根因 A — NFC/NFD 路径比较漏查】scan_workspace() 入库 ref_path 用 format!("{ws.id}/{rel}")；前端点击后 openDoc(item.path) 传回后端 read_file(path) 第一步 files.iter().find(|f| f.path == path) 做 Rust 字符串严格 ==。Mac HFS+ / Samba NAS 返回中文路径为 NFD（Unicode 分解式）；Win NTFS/大多数应用生成为 NFC（合成式）。视觉上完全相同的「江西电信」四个字，NFC/NFD 字节序列不同 → == 返回 false → cache 命中失败，fallback 到磁盘重新读取时若 canonicalize 再引入 UNC/短名前缀差异进一步错位 → 直接 404 或空白。修复：引入 unicode-normalization crate，新增顶部 nfc() / nfc_basename() 辅助；scan_workspace ref_path 入库前先 nfc；read_file 输入端先 nfc；save_file cache 更新比较也先 nfc，全链路 ref_path 字节序列同源。
  • 【根因 A 附加 — 三级弱匹配兜底】主路径 cache==/NFC 都 miss 后，新增三级 basename 弱匹配 (a) basename NFC 精确相等+同 workspace 唯一 (b) 去掉尾部数字/分隔符后缀（MR622-MK vs MR622-MK-副本）再唯一 (c) 全局 workspace 内 basename 全局唯一。命中则强制把返回 FileEntry.path 对齐到 cache 同源 ref_path，保证 save_file/refresh_cache 后续继续命中同一 entry，不直接 404。
  • 【根因 B — 空内容空白屏无 UI 提示】content=="" 通过 typeof doc.content!=="string" → els.markdownView.innerHTML="" → 左编辑器无 placeholder → 全白无任何视觉反馈。修复：openDoc 刚过数据完整性校验插入 isEmptyContent=doc.content.trim()==="" 判断，右侧阅读栏灰底虚线卡片展示「📄 本文档暂无内容 + WPS/Word/江西电信 MD 记事本另存为 UTF-8 + 改名 ASCII 短名+从 NAS 拷到本地盘」两步急救方案；识别出的非 UTF-8 编码（doc.encoding）红字展示，含 U+FFFD 替换字符时额外提示。左侧编辑器同步写多行空内容占位符；命中 isEmptyContent 时显式跳过 renderReaderContent 防止把 tip 清空。
  • 【根因 B 附加 — Worker 异常可见】renderReaderContent Worker catch 分支在 markdownView 顶部 prepend 红色警告 banner「Markdown 渲染服务出现异常，已切换到本地渲染模式」+ error.message；requestMarkdownRender ensureMarkdownWorker 返回 null 时首次 toast 一次「Markdown 渲染服务降级，已切换到主线程渲染」（限频一次不再打扰），两处都不再只 console.error 静默。
  • 【根因 C — GBK/UTF16/UTF8-BOM/UTF32 智能编码解码兜底】江西电信 WPS 导出 md 默认中文 Win 区域设置=GBK/GB18030；记事本另存产生 UTF-16 LE BOM / UTF-8 BOM；scan_workspace & read_file 此前都 std::fs::read_to_string 严格 UTF-8 → FromUtf8Error → continue/404。修复：引入 encoding_rs crate；顶部新增 decode_utf32()（encoding_rs 未单独导出 UTF_32_LE/BE 静态，自编每 4B u32→char）+ decode_bytes_smart() 优先级链 = UTF-8 strict → BOM(UTF-8 / UTF-16 LE / UTF-16 BE / UTF-32 LE / UTF-32 BE) → encoding_rs 候选序列 GB18030→GBK→BIG5→SHIFT_JIS→EUC_KR→WINDOWS_1252（启发：no-error 或 替换率<0.1% 接受）→ 终极 UTF-8 lossy 兜底。scan_workspace & read_file 都改为先 fs::read 取 bytes 再 decode。
  • 【编码标签 + 日志反查】read_file 把 encoding_detected 写入返回 FileEntry.encoding → 前端 state.currentEncoding = doc.encoding 底部状态栏直接显示；若走到 utf-8-lossy 且替换字符>0，log::error! 记录 ref_path + absolute + total_bytes + 首字节 4B hex（管理员日志一眼可定位「江西电信」极端未命中编码的具体文件）。normalize_doc_path 失败 / fs::read IO 失败同样带 abs path + head hex 打 error。
  • 【保持 v1.8.104 全部大升级不回退】bundle.resources 对象映射（强制 $INSTDIR/resources/public）；resolve_public_root 10 条候选 + 编号展示 404 页；7 项导出原生另存为+两按钮+Toast 路径；DOCX/RTF/ODT Rust 正文提取。
